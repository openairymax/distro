# session-baseline.txt — UKUI 会话组件基线（run-smoke.sh T1 的事实源）
#
# 285H 实测（2026-11-16，airymaxos-0.0.4-21 / kernel 6.6.161-alk.13，登录后
# 稳定态、无外部应用）：会话内常驻 21 个组件、合计 23 个进程。首列是内核
# comm（pgrep -x 口径，15 字节截断）。
#
# 判据是「逐项常在」，不是实例数：ukui-screensave 实测 3 个进程（每个输出
# 一台），锁屏实例数随输出数变化，它不是完整性判据。
#
# 第二列可给出判据，缺省即「会话内常驻进程」：
#   dbus:<总线名>    总线按需激活的服务。空闲会话里它本就不常驻，判据是
#                    服务声明在、其 Exec 可执行，进程在位同样成立。
#   gate:<路径>      组件只在对应硬件存在时要求在位；路径缺失时记为 gated，
#                    不算缺项。门控条件与被门控的子系统自己的启动条件同源。
#
# 电量托盘（ukui-power-manager-tray，comm 为 ukui-power-mana）门控到电池：
# 验收机没有任何 power_supply 设备时，同一镜像三条腿里它在位与否不定——
# 进程无设备可显示，起来即退且 journal 不留行，45 秒窗口内时有时无。有电池
# 的机器上它必须常在；托盘入口点是否存在由 T30 单独负责。
#
# 无设备的退出路径还会崩：同轮 UEFI 光盘腿在登录后一秒内留下
# print-fatal-signals 转储与 dumped core，另两条腿未复现（竞态）。因此「门控
# 到电池」有两半，缺一不可：本文件的 gate 判据说明「缺席不算缺项」，
# desktop/xinitrc.d/75-airymax-power-tray.sh 在会话拉起前落用户级 Hidden
# 条目说明「它凭什么不起」。T30 断言抑制条目与 power_supply 的 type 一致。
# 组件增减属产品变更，须同时改本文件与 §8 M4-5 的「23 进程基线」台账。
