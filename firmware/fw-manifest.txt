# fw-manifest.txt — AirymaxOS 固件闭包清单（契约）
#
# 每条一行，三个字段：<包名> <器件类别> <固件路径模式>
#
# 包名     必须由 comps 安装（comps/airymaxos-comps.xml）。清单里出现
#          comps 不装的包，构建期即判红——清单只能是镜像的投影。
# 器件类别 小写字母、数字与连字符。同一类别可有多条，用于按器件汇总
#          核对（D-02/D-03/D-04 要求逐器件可核）。
# 路径模式 绝对路径，必须位于 /usr/lib/firmware 下，允许通配；尾部 `*`
#          兼容发行版把固件存成 .xz/.zst 的形态。
#
# 判定：ci/gates/fw-closure.sh，七件事。
#   ① 集合对账：comps 中名称含 firmware 或以 -ucode 结尾的包，必须全部
#      在本清单出现；清单声明的包必须全部由 comps 安装。
#   ② 实物核对：给 --root（解包后的镜像根）时，逐条模式必须至少命中一个
#      文件。包在而内容不在，正是 D-01「构建期与运行期双判」要拦的形态。
#   ③ 内核 API 对账：给 --kernel 与 --drv 时，驱动经 modinfo 声明的固件
#      名必须在镜像内存在。0.0.3 的 BE200 缺 gl-c0-fm-c0 就是这一项漏判。
#   ④ .pnvm 与 .ucode 成对：只有能力描述没有 ucode 时固件载入失败。
#   ⑤ 标签：命中的固件文件必须是 lib_t，否则 enforcing 下「文件在、载入
#      失败」，内核不给指向性告警。
#   ⑥ 清单回读：本文件随 airymaxos-firmware 落盘
#      /usr/share/airymaxos/firmware/fw-manifest.txt，--root 时与仓库这份
#      逐字比对，并核对同目录的 kernel-abi。只有仓库有清单时，装机后跑
#      判定拿的是发行当天的旧数据，两边分叉而结论仍绿。
#   ⑦ 扁平入口回读：安装期由 fw-flat.sh 按驱动请求名补的软链，装机后
#      必须仍指向同一目标，且生成器 firmware-flat.list 与脚本同在。③ 判
#      「文件在」，这一项判「内核按裸名能取到」——0.0.3 首装无网的两类
#      形态（缺文件、有文件但无入口）各由一项拦。
#
# 本清单是声明面，fw-flat.sh 是执行面：清单决定装哪些固件包，脚本按驱动
# 自报的请求名在安装树里补扁平入口。两者都不列厂商目录——列目录只能修
# 已知的那一块网卡，而 brcmfmac/ath11k/mt76/rtw88 与 ARM、RISC-V 的主用
# 无线走同一条请求名路径。
#
# 只写器件类别与通配路径，不写机型或固件版本号：机型分支会把「换一台同代
# 笔记本」变成改代码（J-23），而固件文件名随上游 linux-firmware 滚动。
# 本文件的模式已按 0.0.3 装机实测核对（linux-firmware 20260309）。
#
# 0.0.3 真机缺陷 D-03：wireless-regdb 未随镜像安装，regulatory.0 加载
# 失败（error -2），5GHz 频段受限。该包包名不含 firmware，名称谓词认不
# 出来，只能由本清单的数据兜底声明。
# ===========================================================================
#
# 无线：Intel Wi-Fi ucode（285H 类机型实测为 gl 家族，模式不锁家族），
#       以及同 stem 的 pnvm 能力描述——0.0.3 的 D-01 正是只带了 ucode
#       家族里较新几档、pnvm 完全缺失；
# 蓝牙：控制器固件 sfi 与设备配置 ddc 成对，缺 ddc 时控制器可枚举但
#       配置失败；显卡：i915 的 GuC/HuC/DMC 都是 i915/ 下的 .bin；
# 监管域：regulatory.db 与其签名，签名文件由尾部通配一并覆盖。
#
# 0.0.4 首装缺陷（285H / BE200，8086:272b）：SP3 的 linux-firmware 已按上游
# 新布局把 Intel Wi-Fi 固件移进 intel/iwlwifi/，顶层不再有同名文件；而
# 6.6.161-alk 的 iwlwifi 只按扁平名请求（modinfo -F firmware 可证），两者
# 交集为空。驱动逐文件报 error -2、收束于 no suitable firmware found，网卡
# 枚举得到、NetworkManager 却报未发现设备。下面两行记录包内真实布局，扁平
# 名由 airymaxos-firmware 的 %post 生成兼容链接补齐；--root 核对时两套路径
# 都必须命中，缺扁平名即判负。
linux-firmware   wifi       /usr/lib/firmware/iwlwifi-*.ucode*
linux-firmware   wifi       /usr/lib/firmware/iwlwifi-*.pnvm*
linux-firmware   wifi       /usr/lib/firmware/intel/iwlwifi/iwlwifi-*.ucode*
linux-firmware   wifi       /usr/lib/firmware/intel/iwlwifi/iwlwifi-*.pnvm*
linux-firmware   bluetooth  /usr/lib/firmware/intel/ibt-*.sfi*
linux-firmware   bluetooth  /usr/lib/firmware/intel/ibt-*.ddc*
linux-firmware   gpu        /usr/lib/firmware/i915/*.bin*
